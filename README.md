# albayda_court

بوابة عربية للاستعلام عن القضايا والجلسات، مع تطبيق Android صغير يفتح النسخة المستضافة. مصدر القضايا وقائمة الجلسات هو ملف `sercase.csv` في Google Drive، وليس خدمة التطبيق الأصلي أو بيانات بوت Telegram.

## الخدمات

- البحث عن القضية برقمها أو باسم المدعي أو المدعى عليه، مع تحديد طريقة البحث ونوع القضية والقاضي.
- قائمة الجلسات اليومية باختيار القاضي أو جميع القضاة، ثم التاريخ أو «اليوم».
- إعلان حضور قابل للتحرير، والبحث بالمحكمة العليا.
- واجهة عربية RTL مع الشعار الرسمي وأيقونات التطبيق.

يُنزّل الخادم ملف CSV مباشرة من Google Drive ويخزّن نسخة مؤقتة في ذاكرة العملية لمدة خمس دقائق. تستخدم واجهة البحث، وقائمة الجلسات اليومية، وإعلان الحضور البيانات نفسها. لا يُحفظ الملف أو سجل القضايا في مستودع Git أو داخل APK.

## الخصوصية والأسرار

المستودع عام؛ لذلك لا ترفع `.env` أو مفاتيح API أو كلمات المرور أو بيانات قضايا فعلية. `.env` مستثنى في `.gitignore`. إعدادات الإنتاج تُضاف في لوحة الاستضافة كمتغيرات سرية، ولا تُضمّن في APK أو مستودع GitHub.

عند النشر، يفرض الخادم تسجيل دخول بكلمة مرور مشتركة، ويستخدم جلسة موقعة في ملف تعريف ارتباط `HttpOnly`, `Secure`, `SameSite=Strict`. لا يُشغّل وضع النشر المحمي إذا غابت أسراره. غيّر كلمة المرور عند الحاجة ولا تشاركها في المستودع أو سجلات Actions.

إذا كان الملف غير متاح للجميع عبر الرابط، يرسل الخادم `GOOGLE_DRIVE_TOKEN` كرأس Bearer إلى Google Drive API. احتفظ به كسرّ في إعدادات الاستضافة فقط، ولا تضفه إلى GitHub أو `.env.example`.

## نشر الخادم من GitHub

يوجد `Dockerfile` و`render.yaml` لإعداد خدمة ويب على Render. بعد ربط المستودع العام بRender وإنشاء الـBlueprint، أضف القيم التالية في لوحة Render **فقط**:

- `GOOGLE_DRIVE_FILE_ID`: معرّف الملف؛ مضبوط مسبقاً على الملف المطلوب.
- `GOOGLE_DRIVE_TOKEN`: رمز OAuth للوصول إلى الملف الخاص، إن لزم. لا ترسله في المستودع ولا في هذه المحادثة.
- `APP_ACCESS_PASSWORD`: كلمة مرور قوية مشتركة لمستخدمي التطبيق.
- `APP_SESSION_SECRET`: قيمة عشوائية قوية لتوقيع جلسات الدخول.

لا تضع كلمات المرور أو رموز الوصول في `render.yaml` أو داخل APK. يبقى التطبيق مغلقاً إذا لم تُضبط متغيرات الحماية. يوفّر `/healthz` فحص الجاهزية فقط ولا يكشف بيانات أو إعدادات.

## بناء APK من GitHub Actions

لا يتطلب بناء Android SDK على جهاز التطوير. بعد نشر الخادم والتحقق من عمل HTTPS:

1. افتح **Actions → Build Android APK → Run workflow** في GitHub.
2. أدخل رابط الخدمة المنشورة بصيغة HTTPS في `app_url`.
3. نزّل artifact باسم `albayda-court-debug-apk` من تشغيل workflow المكتمل، ثم ثبّت `app-debug.apk` على Android.

الـAPK غلاف Android WebView يحمل العنوان المُمرر وقت البناء؛ يتصل بالخادم المستضاف ولا يشغّل Python على الهاتف أو جهاز التطوير. تبقى ملفات PDF في مجلد التنزيلات. الناتج الحالي debug-signed للاختبار، وليس APK إصداراً للنشر في Google Play.

## التشغيل المحلي للاختبار

يتطلب Python 3.10+ واتصالاً بالإنترنت. إذا كان ملف Drive خاصاً، أضف رمز الوصول إلى `.env` محلياً أو متغير البيئة دون مشاركته:

```powershell
Copy-Item .env.example .env
# أدخل GOOGLE_DRIVE_TOKEN عند الحاجة، ولا ترفع ملف .env إلى Git.
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

افتح `http://127.0.0.1:8080`. الوضع المحلي لا يفرض تسجيل الدخول افتراضياً، لذلك لا تعرضه على شبكة عامة.

## الإعدادات

- `GOOGLE_DRIVE_FILE_ID`: معرّف ملف CSV في Google Drive.
- `GOOGLE_DRIVE_TOKEN`: رمز OAuth اختياري للملفات الخاصة.
- `APP_REQUIRE_AUTH`: فعّل المصادقة في الاستضافة (`true`).
- `APP_ACCESS_PASSWORD`: كلمة مرور الدخول (سر).
- `APP_SESSION_SECRET`: مفتاح توقيع الجلسة (سر).
- `ALBAYDA_HOST` و`PORT`: عنوان ومنفذ خادم WSGI.
- `LOG_LEVEL`: مستوى السجل.
